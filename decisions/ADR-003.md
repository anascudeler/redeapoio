# ADR-003 — Estratégia de desenvolvimento incremental por fases

## Status

Accepted

## Contexto

O projeto tem funcionalidades de complexidade e risco técnico bem diferentes: autenticação básica é
simples; acionamento de alerta por botão físico (Volume Up) depende de comportamento específico de
SO/versão de Android/iOS e do estado do app, com limitações conhecidas. Se todas as funcionalidades
forem atacadas ao mesmo tempo, o risco técnico mais incerto (botão físico) pode bloquear a validação
do fluxo de negócio principal (rede de apoio → alerta → notificação), que é o que realmente importa
para testar a hipótese do produto.

## Decisão

O desenvolvimento segue 7 fases sequenciais (ver `spec/architecture/overview.md`), cada uma validada
antes de a próxima começar:

```text
1. Backend básico (User, auth)
2. Rede de apoio (SupportRelationship)
3. Aplicativo mobile (telas + integração)
4. Alerta via botão dentro do app
5. Push notification real
6. Localização no alerta
7. Acionamento por botão físico (Volume Up)
```

O acionamento por botão físico e a arquitetura de `EmergencyTrigger` devem ser desenhados desde já
para que o botão dentro do app e o Volume Up disparem exatamente o mesmo serviço — mas a
implementação do Volume Up em si só ocorre na Fase 7.

## Motivo

- Permite validar o fluxo de negócio central (rede de apoio + alerta + notificação) usando o
  mecanismo de acionamento mais simples e confiável (botão na tela) antes de investir tempo na parte
  de maior incerteza técnica (interceptação de botão físico).
- Reduz o risco de o projeto nunca chegar a um estado testável por estar preso em um problema de
  plataforma específico de SO.
- Localização é tratada como funcionalidade independente e não deve bloquear o fluxo
  alerta → notificação.

## Consequências

- Nenhuma tarefa de uma fase posterior deve ser iniciada antes de a fase anterior estar validada
  (ver `tasks/current.md` e critérios de aceite em `spec/use-cases/`).
- Um agente de IA que perceba oportunidade de "adiantar" uma fase futura deve propor isso
  explicitamente ao desenvolvedor, não implementar por conta própria.
